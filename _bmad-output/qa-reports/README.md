# Quality Reports

This directory contains static quality reports generated by `npm run quality-report`.

Run the command with the Docker stack running for full results:

```bash
# Start Docker stack (required for accessibility audit)
docker compose up -d

# Generate all quality reports
npm run quality-report
```

## Report Files

### `quality-report.json`

Aggregated summary of all quality checks. Shows overall pass/fail and per-section results. Start here.

### `backend-coverage.json`

Backend TypeScript test coverage from c8. Reports lines, statements, functions, and branches percentages against the 70% threshold.

- **Tool:** c8 (built into backend test runner)
- **Source:** `backend/coverage/coverage-summary.json`
- **Threshold:** 70% across all metrics
- **Run independently:** `cd backend && npm test`

### `frontend-coverage.json`

Frontend React component coverage from Vitest + @vitest/coverage-v8.

- **Tool:** Vitest with v8 coverage provider
- **Source:** `frontend/coverage/coverage-summary.json`
- **Threshold:** 70% across all metrics
- **Run independently:** `cd frontend && npm run test:coverage`
- **Known gap:** `App.tsx` is not yet unit-tested (requires React Query mocks). Toaster component is 100% covered. See note in report.

### `e2e-test-report.json`

Playwright end-to-end test results parsed from JUnit XML output.

- **Tool:** Playwright
- **Source:** `e2e/playwright-report/results.xml`
- **Covers:** 18 tests across keyboard navigation, optimistic updates, accessibility, smoke, and basic CRUD flows
- **Run independently:** `npm run test:e2e`

### `security-audit.json`

npm audit results for root, backend, and frontend packages.

- **Tool:** npm audit (built in)
- **Policy:** Zero tolerance for Critical or High severity vulnerabilities (NFR7)
- **Run independently:** `npm audit` (in each package directory)

### `accessibility-audit.json`

axe-core WCAG AA accessibility audit results run via Playwright.

- **Tool:** @axe-core/playwright
- **Requirements:** Docker stack must be running (`docker compose up -d`)
- **Scope:** Full page scan + focused scan on `[data-testid="task-input"]`
- **Standards:** WCAG 2.0 A, WCAG 2.0 AA, best-practice rules
- **Run independently:** `npx playwright test e2e/tests/accessibility.spec.ts --config=e2e/playwright.config.ts`

## Interpreting Results

| Status            | Meaning                                                              |
| ----------------- | -------------------------------------------------------------------- |
| `"passed": true`  | Check met its threshold/requirement                                  |
| `"passed": false` | Check failed threshold — see `belowThreshold` or `violations` fields |
| `"skipped": true` | Check was skipped (e.g., app not running for accessibility)          |

## Known Gaps

1. **Frontend unit coverage:** `App.tsx` is not unit-tested. The file contains the full React/React Query application. Writing integration-level unit tests requires MSW or similar API mocking. The Toaster component (100% covered) demonstrates the test infrastructure is working. Expanding coverage is a follow-up task.

2. **Backend moderate vulnerabilities:** `npm audit` in the backend shows 24 moderate vulnerabilities in dev dependencies. None are Critical or High — policy passes per NFR7.
